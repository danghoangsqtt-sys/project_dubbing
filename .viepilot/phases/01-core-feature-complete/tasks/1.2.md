# Task 1.2 — Canonical Segment, State and Provenance Migration

## Status

`in_progress` — started 2026-09-10.

## Objective

Introduce a versioned canonical project/segment contract that safely migrates existing CapCap JSON projects without losing manual text or speaker/voice choices. Segment IDs must remain stable and unique, `original_text`, `subtitle_vi`, and `dubbing_vi` must persist independently, project and artifact writes must be atomic, and cache signatures must include the producer/configuration provenance that changes generated output.

## Best Practices

- Keep domain/state modules independent of PySide6 and concrete engines.
- Treat input dictionaries as untrusted: validate types/timing/IDs and copy nested mutable data.
- Never overwrite the only legacy project copy; create a sibling schema-version backup before atomic replacement.
- Write UTF-8 JSON to a sibling temporary file, flush and `fsync`, then use `os.replace`.
- Preserve unknown legacy top-level and segment metadata so migration is non-destructive.
- Keep legacy accessors during the brownfield transition, but serialize canonical field names only.
- Hash canonical, sorted JSON with SHA-256; exclude secrets and include every producer/configuration value that changes output.
- Use standard-library deterministic tests with temporary directories; no GPU, model download, media processing, or network access.
- Preserve the four pre-existing dirty files (`CapCap.spec`, `requirements-local.txt`, `ui/worker_adapters/__init__.py`, `ui/worker_adapters/processing_workers.py`).
