## File-Level Plan

- `app/network_policy.py` — centralize Offline Lock and reject non-loopback HTTP(S) before any provider request.
- Translation providers/orchestrator — enforce policy at the network boundary, use configured AI as Hybrid primary with Google web fallback only when online, keep Ollama local-only under Offline Lock, honor optimization, and return actionable failures.
- Translation mapping/validation — retain stable IDs and metadata; flag missing source numbers and Latin proper-name/product tokens without accepting malformed cue mappings.
- `app/workflows/prepare_workflow.py` — stop overriding the caller’s optimization choice and persist translation/dubbing stage facts.
- `app/workflows/voice_workflow.py` — run the initial dubbing rewrite when enabled, validate it, store `dubbing_vi`, and always make TTS prefer it independently of manual-edit flags.
- UI entry points — propagate the chosen optimization value into the worker and signature. Only the single relevant line in the pre-existing dirty worker file will be staged; the user’s unrelated RuntimeAssets removal remains unstaged.

## Best Practices

- Enforce Offline Lock below UI controls at every provider request boundary.
- Allow loopback Ollama in Offline Lock, block public cloud and Google web endpoints.
- Never silently use an online fallback while offline.
- Preserve cue IDs/count/order and source metadata through every translation/rewrite.
- Treat names/numbers validation as visible QA flags; never fabricate replacements.
- Keep subtitle and spoken dubbing text independently editable.
- Use deterministic mocks; tests must make zero external requests.
- Preserve all unrelated user-owned working-tree changes.
