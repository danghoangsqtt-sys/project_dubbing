## Best Practices

- `ProjectState` and canonical segments remain authoritative; the dialog edits a deep copy and emits an explicit staged command.
- Stable cue IDs/count/order and `original_text` are immutable in the review UI.
- Validate timestamps before changing project state; failed validation leaves all in-memory and persisted fields untouched.
- Keep `subtitle_vi` and `dubbing_vi` independent. A subtitle-only edit must not clear or overwrite manually edited dubbing.
- Invalidate by dependency: every content/timing edit invalidates final export; only dubbing/timing changes invalidate assembled TTS/mix artifacts, while cue caches remain content-addressed.
- UI copy is Vietnamese, status is encoded by text as well as color, focusable controls remain keyboard reachable, and design tokens use `#4ED0B3`, `#121B2B`, `#8AD7FF`, `#FF6B6B`, `#54D18B`, `#FFD400`, Segoe UI and 8 px spacing increments.
- Deterministic tests run offscreen and never download models, use the GPU or call outbound services.

## Acceptance Criteria

- [ ] Review table clearly exposes stable cue, start/end, read-only **Bản gốc**, editable **Phụ đề VI**, editable **Lồng tiếng VI**, and textual issue status.
- [ ] Search and filters cover all cues, needs review, low confidence, timing overflow and terminology/name/number issues with visible counts.
- [ ] Editing one Vietnamese field never overwrites the other; source text and stable cue IDs/count/order remain unchanged after save/reopen conversion.
- [ ] Timestamp edits are validated and synchronized to source/translated tracks; invalid timing applies no partial changes.
- [ ] Save applies staged changes explicitly and invalidates only dependent assembled artifacts; subtitle-only edits preserve valid dubbing audio.
- [ ] Primary review/rewrite entry points and user messages follow the approved Vietnamese hierarchy and design tokens.
- [ ] Target/full tests, compilation and `git diff --check` pass; commits/tags are durably pushed without including unrelated worktree changes.
